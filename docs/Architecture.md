# ארכיטקטורה

## שלוש שכבות

### שירות Windows

`Guardian.Service` הוא מקור האמת של לוח הזמנים. הוא קורא את ההגדרות מתיקיית ProgramData, מחשב מדיניות, ומעדכן את מתאם חומת האש. חלון הניהול אינו נדרש כדי שהמדיניות תמשיך לפעול.

### Native Host

`Guardian.NativeHost` משתמש בפרוטוקול Native Messaging של Chrome/Edge. התוסף שולח כתובת חשבון ושם שירות, וה־Native Host מחשב החלטה מתוך קובץ תצורה לקריאה בלבד. נתיב הקובץ קבוע ל־`ProgramData`; משתנה סביבה של הדפדפן אינו יכול לבחור קובץ חלופי.

### תוסף

התוסף פועל על שירותי Google נבחרים, קורא את רשימת החשבונות מ־`ListAccounts`, ומבצע בדיקה חוזרת אחרי ניווט ושינויים דינמיים. הוא אינו מסתמך על `/u/0` לבדו.

## הפרדת הרשאות

- אישור דפדפן = מותר להפעיל את הדפדפן תמיד.
- חסימת אתר = כלל־מחשבית ברמת Windows.
- חסימת Google = לפי חשבון פעיל בטאב.
- חריגה או ביטול חסימה = פעולה נפרדת שמחייבת מנהל.

## Guest וגלישה פרטית

מדיניות Guest נוצרת ברמת Chrome/Edge. שינוי מדיניות בזמן ריצה עשוי להצריך אתחול דפדפן. גלישה פרטית צריכה לקבל את התוסף דרך מדיניות מנוהלת; אם אין דרך להבטיח זאת, הדפדפן או המצב הפרטי צריכים להיחסם בזמן חסימה.

## חסימת אתרים

מתאם המקור משתמש ב־Windows Firewall dynamic FQDN keywords. הוא אינו משנה את שרתי ה־DNS, אך Windows עדיין משתמשת בפתרון השמות הרגיל כדי לאתר כתובות. Microsoft מתעדת מגבלות עבור DoH, Proxy, VPN וכתובות שנשמרו במטמון. לכן המצב הראשוני הוא `AuditOnly`, והמעבר ל־`Enforced` צריך להתבצע רק לאחר בדיקה מול נטפרי.

## זיהוי חשבון Google

אין API ציבורי יחיד שמחזיר תמיד את החשבון הפעיל בכל שירות Google. המימוש הנוכחי הוא שכבת זיהוי ראשונה המבוססת על מאפייני DOM כמו `aria-label`, `data-email` ו־title. לכל שירות יידרשו בדיקות תאימות משלו, ויש להשאיר אפשרות לעדכן את התוסף כאשר Google משנה את הממשק.
