# מדריך הרצה ניסיונית — שומר זמן מסך 0.4.8

המדריך מיועד לבדיקה מבוקרת לפני שימוש אמיתי. אין לדלג על שלבים, ואין להתחיל עם כללים חשובים או עם חסימת דפדפנים.

## כללי בטיחות

- בצע את הבדיקה במחשב שאפשר לשחזר ממנו גיבוי.
- האדם שמגדיר את סיסמת הניהול חייב להיות ההורה או המנהל, ולא המשתמש שאמור להיות מוגבל.
- לפני תחילת הבדיקה ודא שיש חשבון Windows נפרד עם הרשאות מנהל, ושיש משתמש בדיקה רגיל ללא הרשאות מנהל.
- שמור עותק של חבילת ההתקנה ושל קובץ התצורה לפני כל שינוי.
- אל תפעיל בשלב הראשון `BlockUnapprovedBrowserLaunch`.
- אל תעבור ל־`Enforced` עבור אתרים לפני שבדיקת `AuditOnly` הסתיימה בהצלחה.
- מנגנון העדכונים האוטומטי כבוי כברירת מחדל. אפשר להפעיל אותו רק מלוח הבקרה, ורק לאחר הגדרת manifest ב־HTTPS, מפתח ציבורי RSA וחתימות תקינות.

## א. הכנת המחשב

1. צור נקודת שחזור של Windows או גיבוי מלא.
2. התחבר לחשבון מנהל נפרד.
3. סגור את Chrome, Edge וכל תוכנה שהוגדרה בגרסה הישנה.
4. אם מותקנת גרסה קודמת, פתח PowerShell כמנהל ועבור לתיקיית הסקריפטים של הגרסה הקודמת. הרץ:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Uninstall-Service.ps1
```

5. אם יש ספק שהגרסה הישנה השאירה מדיניות דפדפן, אל תמשיך. בדוק את `chrome://policy` ואת `edge://policy`, ושחזר מדיניות רק לאחר שיש לך דרך חזרה.

## ב. פריסת קבצי הגרסה

1. הורד מ־GitHub Actions את ה־artifact של `package` שהסתיים בהצלחה.
2. חלץ אותו לתיקייה זמנית, למשל `C:\Temp\ScreenTimeGuardian-0.4.8`.
3. ודא שקיימות התיקיות `Service`, `ControlPanel`, `NativeHost`, `Agent`, `Updater`, `Extension`, `Policies` ו־`Docs`.
4. העתק את תוכן החבילה אל:

```text
C:\Program Files\ScreenTimeGuardian
```

5. אל תעתיק קובצי תצורה אישיים לתיקיית ההתקנה. הנתונים נשמרים ב־`C:\ProgramData\ScreenTimeGuardian`.

## ג. התקנת השירות בלבד

פתח PowerShell כמנהל והריץ:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
cd 'C:\Program Files\ScreenTimeGuardian\Policies'
.\Install-Service.ps1 `
  -ServiceExecutable '..\Service\ScreenTimeGuardian.Service.exe' `
  -StartAfterInstall
```

בדוק שהשירות קיים ופועל:

```powershell
Get-Service -Name ScreenTimeGuardian
```

התוצאה הרצויה: `Status` הוא `Running`.

פתח את לוח הבקרה:

```powershell
Start-Process 'C:\Program Files\ScreenTimeGuardian\ControlPanel\ScreenTimeGuardian.ControlPanel.exe'
```

בהפעלה הראשונה קבע סיסמת ניהול ארוכה. אל תמסור אותה למשתמש הבדיקה.

## ד. בדיקת מצב בטוח ומתג חירום

1. בלוח הבקרה פתח את לשונית הבטיחות.
2. ודא שהשירות אינו במצב בטוח.
3. אם הוא במצב בטוח לאחר התקנה נקייה, עצור ובדוק את יומן השירות לפני ביטולו.
4. לבדיקת חירום מבוקרת, פתח PowerShell כמנהל והריץ:

```powershell
cd 'C:\Program Files\ScreenTimeGuardian\Policies'
.\Emergency-Disable.ps1
```

5. ודא שהאכיפה נעצרת.
6. מחק את הקובץ `C:\ProgramData\ScreenTimeGuardian\SAFEMODE` רק לאחר שהבדיקה הסתיימה ובאישור מנהל.
7. אם אין שליטה, השאר את הקובץ והסר את השירות. אין להמשיך כאשר מתג החירום אינו עובד.

## ה. בדיקת כלל אפליקציה עם השהיה אפס

1. השתמש באפליקציה שאינה קריטית, לדוגמה תוכנת בדיקה ייעודית.
2. בלוח הבקרה צור כלל חדש עם קובץ ההפעלה המלא.
3. בחר משתמש Windows רגיל אחד בלבד אם זו האפשרות הרצויה.
4. קבע חלון קצר שמתחיל בעוד כמה דקות.
5. השאר **השהיית אכיפה** על `0`.
6. שמור את ההגדרה.
7. כשהחלון מתחיל, בדוק שהאפליקציה עדיין נפתחת אך אינה מצליחה להתחבר לרשת.
8. בדוק שאפליקציות אחרות ואתרי אינטרנט רגילים ממשיכים לעבוד.
9. סגור את לוח הבקרה וחזור על הבדיקה. האכיפה חייבת להמשיך לפעול כשהלוח סגור.

## ו. בדיקת השהיה של 30 שניות

1. ערוך את אותו חלון זמן וקבע **השהיית אכיפה** ל־`30`.
2. שמור והמתן לתחילת חלון חדש.
3. במהלך 30 השניות הראשונות בדוק שהאפליקציה והאינטרנט שלה עדיין זמינים.
4. לאחר 30 שניות, ובתוך לכל היותר מחזור שירות אחד נוסף של 15 שניות, בדוק שחוק חומת האש מופעל והחיבור נחסם.
5. בדוק שהערך נשמר לאחר סגירה ופתיחה מחדש של לוח הבקרה.
6. חזור על הבדיקה עם חלון שחוצה חצות ועם חלון `AllDay`.
7. אם החסימה מתחילה לפני הזמן או אינה מתחילה, עצור את הבדיקה והפעל את מתג החירום.

## ז. בדיקת אתרים כללית

1. השאר את `WebsiteEnforcement` על `AuditOnly`.
2. השאר את "אשר החלה על כל חשבונות המחשב" כבוי בשלב האבחון, עד שסקריפט האבחון יאשר שהמנגנון זמין.
3. הוסף דומיין בדיקה שאינו קריטי.
4. בדוק את הדומיין ואת תת־הדומיין שלו.
5. ודא שדומיין אחר אינו נחסם.
6. רק אם התוצאות תקינות, העבר את המדיניות ל־`Enforced` דרך לוח הבקרה.
7. בדוק שוב את הגלישה הרגילה ואת שירות הסינון הקיים במחשב.

## ח. התקנת התוסף לבדיקה

התקנה ידנית מיועדת לניסוי בלבד ואינה הגנה מלאה:

1. פתח `chrome://extensions`.
2. הפעל Developer mode.
3. בחר Load unpacked ובחר את התיקייה `Extension`.
4. שמור את מזהה התוסף של Chrome.
5. אם בודקים גם Edge, פתח `edge://extensions`, טען את אותה תיקייה ושמור את מזהה התוסף של Edge. המזהים עשויים להיות שונים.
6. פתח PowerShell כמנהל והריץ:

```powershell
cd 'C:\Program Files\ScreenTimeGuardian\Policies'
.\Register-NativeHost.ps1 `
  -ExtensionId '<מזהה Chrome בן 32 אותיות>' `
  -EdgeExtensionId '<מזהה Edge בן 32 אותיות>'
```

7. סגור ופתח מחדש את הדפדפנים.
8. בדוק את דף התוסף ואת יומן השגיאות. אם Native Host אינו מתחבר, עצור כאן.

## ט. בדיקת חשבון Google

1. התחבר ב־Chrome לחשבון Google בדיקה.
2. הוסף את החשבון ואת השירות `gmail` או `youtube` בלוח הבקרה.
3. קבע חלון קצר עם השהיה `0`.
4. בדוק שהשירות נחסם בזמן החלון.
5. התחבר לחשבון Google אחר ובדוק שאינו נחסם על ידי כלל החשבון.
6. בדוק מעבר בין פרופילים, יציאה מהחשבון וחזרה אליו.
7. כבה זמנית את השירות או את ה־Native Host רק בסביבת בדיקה. בזמן שהשירות אינו זמין, התוסף משתמש במדיניות האחרונה הידועה ואינו מוחק כללי חסימה קיימים. זו שכבת המשכיות, לא תחליף לפריסה מנוהלת.

## י. בדיקת מדיניות דפדפן מנוהלת

אין להריץ את הסקריפט עם כתובות ברירת מחדל או עם תוסף מקומי. פריסה מנוהלת דורשת תוסף שפורסם במקור הפצה מתאים וכתובות עדכון HTTPS אמיתיות.

דוגמה כללית בלבד:

```powershell
cd 'C:\Program Files\ScreenTimeGuardian\Policies'
.\Set-BrowserPolicies.ps1 `
  -ExtensionId '<מזהה Chrome>' `
  -EdgeExtensionId '<מזהה Edge>' `
  -UpdateUrl 'https://שרת-הארגון.example/chrome/update.xml' `
  -EdgeUpdateUrl 'https://שרת-הארגון.example/edge/update.xml'
```

לאחר מכן:

1. סגור ופתח מחדש את הדפדפנים.
2. פתח `chrome://policy` ו־`edge://policy`.
3. לחץ Reload policies.
4. ודא שאין שגיאות וש־ExtensionInstallForcelist מופיע.
5. ודא ש־ExtensionSettings אינו מכיל `"*": "blocked"` וש־BlockExternalExtensions אינו מופיע מטעם Guardian.
6. בדוק שהמשתמש הרגיל אינו יכול להסיר את התוסף, ובמקביל שתוסף בדיקה אחר עדיין ניתן להתקנה.


אם אין מקור הפצה מנוהל, השאר את מדיניות הכפייה כבויה והשתמש בהתקנה ידנית לצורך בדיקה בלבד.

## יא. בדיקת אתחול ושחזור

1. ודא שמתג החירום ידוע ונגיש.
2. אתחל את Windows.
3. ודא שהמערכת עולה ושאפשר לפתוח את לוח הבקרה.
4. בדוק שהשירות פועל:

```powershell
Get-Service -Name ScreenTimeGuardian
```

5. בדוק שוב את כלל האפליקציה ואת כלל האתר.
6. בדוק שהמשתמש הרגיל אינו יכול לכתוב ל־`C:\ProgramData\ScreenTimeGuardian\config.json`.
7. בדוק שהאינטרנט הכללי לא נותק.

## יב. תנאי הצלחה

התקנה ניסיונית נחשבת מוצלחת רק אם כל אלה עברו:

- השירות פועל לאחר אתחול.
- סיסמת הניהול נדרשת לשינוי.
- כלל אפליקציה עם `0` נאכף בזמן.
- כלל אפליקציה עם `30` שניות מתחיל לאחר ההשהיה, עם סטייה אפשרית של עד מחזור השירות בן 15 השניות.
- חלון שחוצה חצות וחלון `AllDay` מתנהגים נכון.
- סגירת לוח הבקרה אינה עוצרת אכיפה.
- דומיין שאינו ברשימה נשאר נגיש.
- משתמש Windows אחר אינו נפגע מכלל שמוגבל ל־SID אחד.
- מתג החירום עוצר אכיפה.
- אתחול אינו יוצר לולאה.
- לא הופעלה חסימת דפדפנים לא מאושרים לפני שכל הבדיקות האחרות עברו.

## יג. מה עושים במקרה תקלה

סדר הפעולות:

1. עצור שינויי תצורה.
2. הרץ כמנהל:

```powershell
cd 'C:\Program Files\ScreenTimeGuardian\Policies'
.\Emergency-Disable.ps1
```

3. אם אין שליטה, צור את הקובץ:

```powershell
New-Item -ItemType File -Force 'C:\ProgramData\ScreenTimeGuardian\SAFEMODE'
```

4. בדוק שהשירות במצב בטוח.
5. אם עדיין יש בעיה, הרץ `Uninstall-Service.ps1` כמנהל.
6. רק לאחר שהמחשב חזר למצב תקין, שמור את הודעת השגיאה ואת הזמן שבו הופיעה.

## ידוע מראש

המערכת אינה מספקת הגנה מלאה מפני מנהל מקומי, שינויי מדיניות ארגוניים, VPN, Proxy, DoH, דפדפן שאינו מנוהל או הסרה ידנית של תוסף. רק בדיקת Windows בפועל יכולה לאשר את ההתנהגות במחשב מסוים.
